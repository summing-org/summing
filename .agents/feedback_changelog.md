Каждый подведённый итог после любых изменений должен попадать в
дневной changelog-фрагмент `.changes/${UTC-date}.md` как новая запись.
`CHANGELOG.md` в корне репозитория остаётся индексом фрагментов, а не
местом для длинных записей.

**Why:** пользователь хочет устойчивую историю решений, а не только
git-сообщения. Документация проекта должна отражать архитектурные
детали (формат ключей, инварианты, race-поведение), которые легко
теряются между коммитами. Был явный запрос 2026-04-15: "возьми за
правило каждый подведённый тобой итог после любых изменений вносить
в changelog".

**How to apply:**

- После завершения значимой итерации (feature, refactor, backend
  stage, UI page) сначала пишу короткий итог пользователю в чате, затем
  делаю развернутый итог и пишу его в `.changes/${UTC-date}.md`.
- Внутри дневного файла новая запись добавляется сразу под заголовком
  `# ${UTC-date}`, чтобы новые итоги за день были сверху.
- Если дневного файла ещё нет, создать его с заголовком
  `# ${UTC-date}` и затем добавить запись.
- `CHANGELOG.md` обновлять только как индекс: добавить ссылку на новый
  дневной файл, если такой даты в индексе ещё не было.
- Если итерация маленькая (опечатка, тривиальный фикс), changelog
  можно не трогать — правило про "значимые изменения".
- Коммитить `.changes/*` и индекс `CHANGELOG.md`
  вместе с кодом той же итерации, не отдельно.
