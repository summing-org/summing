# 2026-08-24

## Preserve active runner jobs during deployment checks

- Made the project-runner host installer compare the installed rootless Docker configuration and
  systemd unit before restarting either daemon. A periodic no-change deployment now repairs file
  ownership and enablement without interrupting running jobs or persistent services; the Project
  Viewer installer no longer adds a redundant unconditional runner restart afterward.
- Added bounded runner draining for required Docker or runner restarts and included both active and
  queued runner jobs in the main deployment drain. Release deployment rechecks the workload after
  configuration sync immediately before restarting services.
- Added deployment-asset regressions for the guarded restart ordering, workload counters, and drain
  timeout propagation.

## Route service tools through the authorized runtime control plane

- Fixed the runtime dynamic-tool dispatcher to forward both `runner` and `service` namespaces to
  the shared runner control plane. Previously the service tools were advertised to Codex and
  implemented by the runner, but every live call failed with `unknown host tool namespace`.
- Added runtime-level coverage that exercises `service.inspect` through an active authorized owner
  turn, closing the gap left by direct service-tool unit tests.
