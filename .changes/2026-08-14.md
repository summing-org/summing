# 2026-08-14

## Project envs replace Connections

- Replaced provider-specific manifests, tickets, gateway/lease/raw grants and the
  separate Secret Broker with one ordinary dotenv document per project workspace.
  The administrator edits the plaintext document in the new **Энвы** Mini App tab;
  GET/PUT remain authenticated, admin-only and use optimistic revision checks.
- Runner now owns an AES-256-GCM environment store with a mandatory private
  32-byte key. Every validate/dry-run/run captures an encrypted job snapshot,
  materializes one `0600` env-file in runtime tmpfs, injects it through Docker
  `--env-file`, redacts matching log/artifact values and deletes both runtime and
  job snapshots. Build receives no env, validate remains offline, and other jobs
  only receive network when operator config explicitly sets `network: true`.
- Envs are scoped by project and workspace; runner jobs and schedules carry the
  workspace id. Existing static env files can bootstrap the encrypted store once,
  with runner-owned variables removed. Git snapshots and runner archives now strip
  tracked or untracked `.env`/`.env.*` files while retaining `.env.example`, so local
  dotenv files cannot enter Docker build context. The installer creates the runner key but
  deliberately leaves an existing legacy broker/data untouched for rollback.
  Removed obsolete broker code, units, Caddy route, configuration and tests; added
  migration/runbook documentation and advanced SUMMING to 9.3.0.

## ash-seo migrated to encrypted Connections

- Installed and enabled the production `summing-secrets` broker, generated its
  host-local master/ticket keys, added the `/connections` Caddy route, and kept the
  ash-seo publication timer disabled. Migrated the existing OpenAI, Telegram MTProto,
  and Telegram Bot credentials from the static project env into encrypted project-level
  raw Connections; the static env now contains only non-secret runtime switches.
- Added and committed ash-seo's `.summing/integrations.json` at `545f16b`, then verified
  the migration with dry-run `739ea0dd-ba40-4bc2-ae88-b5abe1f41705`: all 30 Telegram
  sources were read without failures, 500 source items produced 266 candidates and 27
  planned posts, and all six detailed artifacts were persisted. This also confirms the
  earlier `/var/lib/summing-runs` systemd write-path fix end to end.
- Release activation did not perform this migration automatically by design: it only
  restarts an already provisioned broker and never copies legacy credential values or
  grants raw project access without an explicit operator migration.

## Bare bot mentions stay local

- A message containing only the bot's `@mention` in an unbound Telegram topic now
  receives a concise prompt to include a question instead of starting a projectless
  Codex thread and exposing a low-level App Server error.
- The ping is handled before participant quota, volatile context, and the projectless
  worker queue, while substantive mentions and replies keep their existing isolated
  Q&A behavior. Low-level projectless startup/runtime failures remain in server logs and
  are replaced by a concise retry message in Telegram. Added routing and error-boundary
  regressions and advanced SUMMING to 9.2.3.

## Linked-worktree Git metadata remains writable for Project owners

- Owner/editor runs now carry the project-scoped common Git directory alongside the
  conversation worktree in `runtimeWorkspaceRoots` for `thread/start`, `thread/resume`,
  and `turn/start`. This prevents a turn override from silently dropping the linked
  worktree metadata root and blocking `fetch`, commit, or rebase.
- Read-only participant and projectless turns still exclude every Git metadata root.
  Added App Server contract regressions for write/read-only start, resume, and turn
  boundaries, documented the invariant, and advanced SUMMING to 9.2.2.
