# 2026-08-14

## Project administration moves into a dedicated Mini App

- Added an administrator-only `/admin` Mini App that does not require an existing
  Conversation. It presents the Project catalog, discovered Telegram groups/topics,
  current bindings and busy state in a responsive control center; every bound topic
  links directly to its existing Project Viewer.
- Administrators can create an empty managed Git repository or clone a remote and
  bind/rebind a discovered supergroup topic by selecting Project and Workspace.
  Rebinding refuses active processors, turns and pending inputs, preserves the
  existing thread/worktree reset invariant and clears volatile unbound context.
  Telegram `initData` and the exact administrator ACL protect all new APIs; project
  owners cannot enumerate or mutate the global catalog.
- Runtime now installs a per-administrator **Управление** Mini App menu button and
  `/start` returns the same UI entry point. Slash commands remain a documented
  recovery/compatibility surface. Added API, asset, responsive-layout, Telegram
  payload and runtime-routing regressions, visually checked desktop/mobile layouts,
  updated onboarding documentation and advanced SUMMING to 9.4.0.

## Project repositories can connect origin with an isolated SSH deploy key

- Added an SSH-first onboarding card to the Mini App **Репозиторий** tab. A
  Project owner or administrator can enter a missing `origin`, copy the generated
  public Ed25519 deploy key, add it to the Git provider with write access and
  verify connectivity without leaving the repository workflow. An existing SSH
  origin can receive a managed key without changing its URL; an existing remote
  can never be replaced through this API.
- Managed private keys live outside repositories and worktrees under
  `$SUMMING_DATA_DIR/repository-credentials/<project>/<workspace>/` with private
  directory/file modes. The API exposes only the public key and SHA-256
  fingerprint. Managed Git operations ignore user SSH config and agents, use one
  fixed key without prompts, isolate `known_hosts`, trust the first host key once
  and reject later changes. Existing externally configured SSH/HTTPS credentials
  remain compatible. Fresh installs and upgrades now require `openssh-client` for
  the fixed `ssh`/`ssh-keygen` executables.
- Connection setup shares the existing repository-wide operation lock and active
  Codex-run exclusion. Added regressions for ACLs, busy conversations, SSH URL
  validation, remote replacement refusal, symlinked credential directories,
  stable key generation, file modes and private-data omission; documented backup
  and recovery of deploy keys and advanced SUMMING to 9.3.3.

## Project owners can synchronize their conversation branch with origin

- Added a dedicated **Репозиторий** Mini App tab for the current conversation
  worktree. The administrator and assigned Project owner see the sanitized
  `origin`, branch and HEAD together with ahead/behind, unpublished, dirty,
  diverged and connectivity states; other Telegram users remain outside the
  existing Project ACL.
- Added explicit one-click Pull and Push backed by fixed, conservative Git
  operations. Push sends only the displayed committed HEAD to the same-named
  remote branch and never forces or auto-commits. Pull fetches/prunes origin and
  only fast-forwards a clean worktree from its same-named remote branch, or from
  the detected default branch before first publication. Dirty and diverged
  states are left untouched for an explicit merge/rebase.
- Repository mutations use optimistic full-SHA checks, serialize across all
  conversation worktrees sharing one Git directory and stop while the selected
  Conversation's Codex turn is active. Added Git and Viewer API
  regressions for owner/admin authorization, participant denial, active-run
  exclusion, publication, remote-ahead Pull, dirty worktrees, stale buttons and
  non-fast-forward rejection; documented non-interactive write credentials and
  advanced SUMMING to 9.3.2.
- Git subprocesses cross the sandbox boundary with a minimal environment that
  excludes application secrets, disables repository hooks/fsmonitor, validates
  SSH/HTTPS endpoints without embedded tokens and refuses project-local command
  hooks hidden in includes, URL rewrites, credential/SSH overrides or executable
  filters. Trusted credentials remain global to the `summing` Unix account.

## Connections credentials survive the 9.3 env cutover

- Added a compatibility bootstrap for hosts still running the legacy runner unit:
  the runner opens its local socket fail-closed while the `summing`-owned
  coordinator reads the manifest/archive from the pinned Git SHA and hands them
  across the existing group boundary. The repository-blind runner creates or
  reuses one private AES key, leases every project-granted raw credential, merges
  it with the non-secret static env and persists only encrypted data plus
  value-free metadata. Import is idempotent, releases and blanks the legacy lease,
  rejects OAuth/gateway shapes and keeps the old deploy health rollback effective.
- The healthy runner now verifies the migrated environment with sequential Validate
  and Dry run jobs on the pinned Git SHA and one current env revision, retrying
  failures without blocking the Mini App. A root-only, transactional deploy hook
  finalizes only a current verification: it preserves recovery copies, converts
  `envPath`, installs and health-checks the new runner unit, removes only the exact
  legacy Caddy route and disables Secret Broker last. Any error restores operational
  config and broker state; the legacy vault, key and unit are never deleted.
- Documented the two deploy-tick production sequence, recovery boundary and the
  unavoidable legacy-worker bootstrap ordering; added migration, encryption,
  stale-revision, repository-permission handoff and deployment-asset regressions
  and advanced SUMMING to 9.3.1.

## Project envs replace Connections

- Replaced provider-specific manifests, tickets, gateway/lease/raw grants and the
  separate Secret Broker with one ordinary dotenv document per project workspace.
  The administrator edits the plaintext document in the new **Энвы** Mini App tab;
  GET/PUT remain authenticated, admin-only and use optimistic revision checks.
- Runner now owns an AES-256-GCM environment store with a mandatory private
  32-byte key. Every validate/dry-run/run captures an encrypted job snapshot,
  materializes one `0600` env-file in runtime tmpfs, injects it through Docker
  `--env-file`, redacts matching log/artifact values and deletes both runtime and
  job snapshots. Build receives no env, validate remains offline, and other jobs
  only receive network when operator config explicitly sets `network: true`.
- Envs are scoped by project and workspace; runner jobs and schedules carry the
  workspace id. Existing static env files can bootstrap the encrypted store once,
  with runner-owned variables removed. Git snapshots and runner archives now strip
  tracked or untracked `.env`/`.env.*` files while retaining `.env.example`, so local
  dotenv files cannot enter Docker build context. The installer creates the runner key but
  deliberately leaves an existing legacy broker/data untouched for rollback.
  Removed obsolete broker code, units, Caddy route, configuration and tests; added
  migration/runbook documentation and advanced SUMMING to 9.3.0.

## ash-seo migrated to encrypted Connections

- Installed and enabled the production `summing-secrets` broker, generated its
  host-local master/ticket keys, added the `/connections` Caddy route, and kept the
  ash-seo publication timer disabled. Migrated the existing OpenAI, Telegram MTProto,
  and Telegram Bot credentials from the static project env into encrypted project-level
  raw Connections; the static env now contains only non-secret runtime switches.
- Added and committed ash-seo's `.summing/integrations.json` at `545f16b`, then verified
  the migration with dry-run `739ea0dd-ba40-4bc2-ae88-b5abe1f41705`: all 30 Telegram
  sources were read without failures, 500 source items produced 266 candidates and 27
  planned posts, and all six detailed artifacts were persisted. This also confirms the
  earlier `/var/lib/summing-runs` systemd write-path fix end to end.
- Release activation did not perform this migration automatically by design: it only
  restarts an already provisioned broker and never copies legacy credential values or
  grants raw project access without an explicit operator migration.

## Bare bot mentions stay local

- A message containing only the bot's `@mention` in an unbound Telegram topic now
  receives a concise prompt to include a question instead of starting a projectless
  Codex thread and exposing a low-level App Server error.
- The ping is handled before participant quota, volatile context, and the projectless
  worker queue, while substantive mentions and replies keep their existing isolated
  Q&A behavior. Low-level projectless startup/runtime failures remain in server logs and
  are replaced by a concise retry message in Telegram. Added routing and error-boundary
  regressions and advanced SUMMING to 9.2.3.

## Linked-worktree Git metadata remains writable for Project owners

- Owner/editor runs now carry the project-scoped common Git directory alongside the
  conversation worktree in `runtimeWorkspaceRoots` for `thread/start`, `thread/resume`,
  and `turn/start`. This prevents a turn override from silently dropping the linked
  worktree metadata root and blocking `fetch`, commit, or rebase.
- Read-only participant and projectless turns still exclude every Git metadata root.
  Added App Server contract regressions for write/read-only start, resume, and turn
  boundaries, documented the invariant, and advanced SUMMING to 9.2.2.
