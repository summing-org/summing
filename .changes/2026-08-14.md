# 2026-08-14

## One Conversation Understanding Loop owns both memory and attention

- Removed the independent Project-aware ambient model turn. Human-to-human messages now
  remain durable Team Space evidence and enter one source-local background model pass;
  explicit bot mentions, replies and commands remain immediate direct turns. Legacy
  queued ambient inputs are discarded on restart in favor of their already durable
  journal events, preventing the same conversation from being interpreted twice.
- Replaced the fixed Team Space synthesis timer with an adaptive understanding scheduler:
  20 seconds of trailing quiet, a 90-second hard deadline and an immediate 40-event cap.
  Batches never mix Sources, remain globally serialized, retry with bounded exponential
  backoff, and retain compatibility aliases for the old synthesis config keys.
- Added one validated structured contract for `Conversation Episode`, Team Space summary,
  evidence-backed knowledge, orientation and `silent`/`reply` intervention. Episodes
  preserve speaker/addressee/mentioned roles and evidence-linked intent, include reply
  targets from earlier batches, and are persisted as source-visible knowledge. Silence is
  a successful memory update; invalid boundaries, provenance or reply targets leave the
  complete batch pending.
- Rewrote the constitution, memory contract, README and architecture handbook around the
  single-loop invariant, documented exact triggers, model-call accounting, consent,
  Project isolation, direct-turn behavior and failure semantics, and advanced SUMMING to
  9.5.0. Added regressions for no ambient Project queue, source isolation, shared
  episode/memory/intervention output, config migration, quiet debounce, event cap and hard
  deadline.

## Telegram reply relationships survive routing and synthesis

- Distinguished Telegram's implicit forum-topic root edge from an explicit human
  reply. Ordinary owner messages such as «подтянул, чекай» remain direct editor
  inputs instead of being misclassified as ambient conversation merely because the
  Bot API attaches the topic root as `reply_to_message`.
- Preserved real reply context in durable Project and projectless prompts with the
  quoted message id, sender identity and a bounded credential-safe quote. A bare bot
  mention in a reply now means «respond to this quote» rather than producing a generic
  presence acknowledgement. Mentions added by Telegram edits enter direct routing;
  edits without an explicit bot address remain evidence only.
- Added reply-target snapshots to Team Space synthesis. Startup repairs legacy
  forum-root edges, requeues affected evidence and marks dependent knowledge/summary
  for review so the model can rebuild relationships instead of retaining transport
  artifacts as human intent. Added routing, edit, journal migration and synthesis
  regressions, updated the constitution and handbook, and advanced SUMMING to 9.4.4.

## Topic bindings now notify the assigned project owner

- After a successful new bind or rebind from the Admin Mini App, `/bind_topic` or
  `/bind`, SUMMING now posts into the selected Telegram topic and tells the Project
  owner that this topic is connected to their Project/Repository. The owner is a
  clickable HTML `tg://user?id=...` mention, so delivery does not depend on a public
  username; observed profile text and project metadata are escaped before rendering.
- Kept binding state authoritative and notifications non-disruptive: saving the same
  Project/Repository again emits no duplicate, while a delivery failure is logged
  without rolling back the durable binding. Added callback, runtime, topic-routing
  and Telegram HTML parse-mode regressions, documented the behavior in the Mini App,
  README and handbook, and advanced SUMMING to 9.4.3.

## Admin Mini App summarizes observed users by group and topic

- Added durable `telegram_users` profile metadata and `telegram_topic_users`
  activity keyed by `(chat_id, topic_id, user_id)`. Every available group-message
  author now contributes a scoped message count and first/last-seen timestamps;
  chat summaries aggregate the same user across topics without losing the stable
  Telegram numeric ID.
- Extended the exact-administrator overview with global/chat/topic user counts and
  added a lazy `/api/viewer/admin/users` detail endpoint. The Mini App now expands
  responsive user cards with name, username, Telegram ID, language, bot/premium
  flags, message/topic totals and activity dates, while explaining that Telegram
  Bot API cannot enumerate silent members.
- Kept participant erasure consistent: `/memory_forget_me` removes that user's
  activity in the current Telegram group, and the existing Team Space opt-out stops
  it from accumulating again until `/memory_resume_me`. Added state, runtime, API
  authorization and static UI regressions, updated operator/architecture docs and
  advanced SUMMING to 9.4.2.

## Human-directed owner messages stay ambient and Git sandbox roots mount correctly

- Distinguished editor authority from conversational intent. In a bound Telegram
  group, an administrator or Project owner who leads with another user's mention or
  replies to a human now contributes read-only ambient evidence instead of starting
  or steering a write-capable turn. Commands, bot mentions and replies to the bot
  remain direct. The ambient decision prompt now makes silence the default and
  forbids parroting editor speech; one concise intervention remains possible only
  for a material ambiguity, contradiction, blocker, risk or unresolved decision.
- Replaced worktree-relative permission entries with absolute filesystem grants and
  denies while retaining the project Git metadata directory as a runtime root. This
  prevents the App Server from multiplying `.git` and `.summing-runtime` rules under
  the Git directory and eliminates the synthetic mount failure that hid readable
  runtime context from Codex. Added routing and permission-profile regressions and
  updated the constitution, operator README and architecture handbook; advanced
  SUMMING to 9.4.1.

## Consent-gated Team Space synthesis now turns evidence into understanding

- Added an explicit `team_memory.model_egress_enabled` gate. Before the first
  background batch leaves the local journal, SUMMING announces the exact egress
  surface in the Team Space. Batches run in fresh ephemeral read-only Codex
  threads without Project roots, network, environments or external capabilities.
- Added structured synthesis of summaries, episodes, facts, decisions, tasks,
  questions, risks, terms, people and hypotheses. Runtime validation rejects
  missing or cross-batch evidence, invalid source/person visibility, confidence
  and temporal errors, cross-Space supersession and invented proactive targets;
  failed or interrupted work stays pending and delivery failures are requeued.
- Added a warm-up lifecycle: knowledge accumulates silently until the configured
  evidence threshold, then SUMMING publishes one orientation with its current
  understanding and highest-value questions. Later proactive replies require a
  concrete Telegram evidence event and respect a global per-Space cooldown.
- Strengthened participant erasure for synthesized memory: the participant's event
  content and display names, linked model outputs, knowledge and proactive text are
  cleared; the shared summary becomes hidden `needs-review` state and is rebuilt
  from the remaining evidence rather than deleting other participants' knowledge.
- Added configuration, migration coverage, transport-boundary tests and an
  end-to-end synthesis test covering egress notice, isolation, provenance,
  orientation and proactive reply delivery.

## Team Space begins as a durable, transparent local memory boundary

- Reframed the constitution around Team Space rather than treating an unbound
  topic as disposable transport noise. Admission now creates a durable boundary
  for Sources, People, provider identities, evidence, knowledge, interventions
  and separately linked Projects; observation never grants Project agency, and
  motives remain evidence-linked hypotheses rather than silent facts.
- Added a provider-neutral SQLite journal and Telegram adapter for messages,
  edits, channel posts, reactions and membership events. Ingest happens before
  participant rate limits or reply decisions, survives restart and is preserved
  by `/bind`; duplicate provider delivery is idempotent. The schema owns temporal
  validity, confidence, space/source/person visibility, evidence links,
  supersession and `needs-review` propagation for edits and erasure.
- Added transparent admission notices, bounded raw retention, credential
  interception before persistence, Space pause/resume and participant controls
  `/memory`, `/memory_me`, `/memory_forget_me` and `/memory_resume_me`.
  Erasure redacts event content, invalidates dependent conclusions and disables
  future collection for that identity until explicit resume.
- Documented the remaining trust boundary: local journaling does not authorize
  automatic transmission of all team communication to Codex. Background semantic
  synthesis and proactive questions require explicit consent plus the model-egress
  configuration gate; direct mentions keep their existing bounded projectless Q&A
  boundary.

## Project administration moves into a dedicated Mini App

- Added an administrator-only `/admin` Mini App that does not require an existing
  Conversation. It presents the Project catalog, discovered Telegram groups/topics,
  current bindings and busy state in a responsive control center; every bound topic
  links directly to its existing Project Viewer.
- Administrators can create an empty managed Git repository or clone a remote and
  bind/rebind a discovered supergroup topic by selecting Project and Workspace.
  Rebinding refuses active processors, turns and pending inputs, preserves the
  existing thread/worktree reset invariant and keeps the durable Team Space
  evidence journal intact across Project changes.
  Telegram `initData` and the exact administrator ACL protect all new APIs; project
  owners cannot enumerate or mutate the global catalog.
- Runtime now installs a per-administrator **Управление** Mini App menu button and
  `/start` returns the same UI entry point. Slash commands remain a documented
  recovery/compatibility surface. Added API, asset, responsive-layout, Telegram
  payload and runtime-routing regressions, visually checked desktop/mobile layouts,
  updated onboarding documentation and advanced SUMMING to 9.4.0.

## Repository setup is diagnosable, reversible, and auditable

- Reworked the Mini App repository workflow into four always-visible steps for
  origin, deploy key, read/write access and branch synchronization. The current
  sanitized origin URL, empty-remote publication action, exact diagnostic code,
  human-readable failure reason and last verification time are now explicit.
- Added independent `ls-remote` read verification and non-mutating
  `push --dry-run` write verification. Managed SSH ignores but reports a legacy
  project-local `core.sshCommand`; an explicit migration removes only that value
  after the managed key has passed both probes.
- Added preflighted origin replacement with optimistic URL checks, confirmation,
  automatic failure rollback and a persisted one-step rollback to the previous
  URL. SSH URL usernames remain visible and are preserved in rollback state;
  HTTP(S) userinfo remains redacted. Added two-phase deploy-key rotation so a
  candidate key is copied and verified while the active key still works, then
  atomically activated or cancelled.
- Persisted bounded repository audit history outside the worktree with actor,
  timestamp, action, outcome, sanitized remote, branch and full HEAD. Added
  integration coverage for dry-run ref safety, legacy migration, URL
  change/rollback, key rotation, state permissions and private-key omission;
  advanced SUMMING to 9.4.0.
## Project repositories can connect origin with an isolated SSH deploy key

- Added an SSH-first onboarding card to the Mini App **Репозиторий** tab. A
  Project owner or administrator can enter a missing `origin`, copy the generated
  public Ed25519 deploy key, add it to the Git provider with write access and
  verify connectivity without leaving the repository workflow. An existing SSH
  origin can receive a managed key without changing its URL; an existing remote
  can never be replaced through this API.
- Managed private keys live outside repositories and worktrees under
  `$SUMMING_DATA_DIR/repository-credentials/<project>/<workspace>/` with private
  directory/file modes. The API exposes only the public key and SHA-256
  fingerprint. Managed Git operations ignore user SSH config and agents, use one
  fixed key without prompts, isolate `known_hosts`, trust the first host key once
  and reject later changes. Existing externally configured SSH/HTTPS credentials
  remain compatible. Fresh installs and upgrades now require `openssh-client` for
  the fixed `ssh`/`ssh-keygen` executables.
- Connection setup shares the existing repository-wide operation lock and active
  Codex-run exclusion. Added regressions for ACLs, busy conversations, SSH URL
  validation, remote replacement refusal, symlinked credential directories,
  stable key generation, file modes and private-data omission; documented backup
  and recovery of deploy keys and advanced SUMMING to 9.3.3.

## Project owners can synchronize their conversation branch with origin

- Added a dedicated **Репозиторий** Mini App tab for the current conversation
  worktree. The administrator and assigned Project owner see the sanitized
  `origin`, branch and HEAD together with ahead/behind, unpublished, dirty,
  diverged and connectivity states; other Telegram users remain outside the
  existing Project ACL.
- Added explicit one-click Pull and Push backed by fixed, conservative Git
  operations. Push sends only the displayed committed HEAD to the same-named
  remote branch and never forces or auto-commits. Pull fetches/prunes origin and
  only fast-forwards a clean worktree from its same-named remote branch, or from
  the detected default branch before first publication. Dirty and diverged
  states are left untouched for an explicit merge/rebase.
- Repository mutations use optimistic full-SHA checks, serialize across all
  conversation worktrees sharing one Git directory and stop while the selected
  Conversation's Codex turn is active. Added Git and Viewer API
  regressions for owner/admin authorization, participant denial, active-run
  exclusion, publication, remote-ahead Pull, dirty worktrees, stale buttons and
  non-fast-forward rejection; documented non-interactive write credentials and
  advanced SUMMING to 9.3.2.
- Git subprocesses cross the sandbox boundary with a minimal environment that
  excludes application secrets, disables repository hooks/fsmonitor, validates
  SSH/HTTPS endpoints without embedded tokens and refuses project-local command
  hooks hidden in includes, URL rewrites, credential/SSH overrides or executable
  filters. Trusted credentials remain global to the `summing` Unix account.

## Connections credentials survive the 9.3 env cutover

- Added a compatibility bootstrap for hosts still running the legacy runner unit:
  the runner opens its local socket fail-closed while the `summing`-owned
  coordinator reads the manifest/archive from the pinned Git SHA and hands them
  across the existing group boundary. The repository-blind runner creates or
  reuses one private AES key, leases every project-granted raw credential, merges
  it with the non-secret static env and persists only encrypted data plus
  value-free metadata. Import is idempotent, releases and blanks the legacy lease,
  rejects OAuth/gateway shapes and keeps the old deploy health rollback effective.
- The healthy runner now verifies the migrated environment with sequential Validate
  and Dry run jobs on the pinned Git SHA and one current env revision, retrying
  failures without blocking the Mini App. A root-only, transactional deploy hook
  finalizes only a current verification: it preserves recovery copies, converts
  `envPath`, installs and health-checks the new runner unit, removes only the exact
  legacy Caddy route and disables Secret Broker last. Any error restores operational
  config and broker state; the legacy vault, key and unit are never deleted.
- Documented the two deploy-tick production sequence, recovery boundary and the
  unavoidable legacy-worker bootstrap ordering; added migration, encryption,
  stale-revision, repository-permission handoff and deployment-asset regressions
  and advanced SUMMING to 9.3.1.

## Project envs replace Connections

- Replaced provider-specific manifests, tickets, gateway/lease/raw grants and the
  separate Secret Broker with one ordinary dotenv document per project workspace.
  The administrator edits the plaintext document in the new **Энвы** Mini App tab;
  GET/PUT remain authenticated, admin-only and use optimistic revision checks.
- Runner now owns an AES-256-GCM environment store with a mandatory private
  32-byte key. Every validate/dry-run/run captures an encrypted job snapshot,
  materializes one `0600` env-file in runtime tmpfs, injects it through Docker
  `--env-file`, redacts matching log/artifact values and deletes both runtime and
  job snapshots. Build receives no env, validate remains offline, and other jobs
  only receive network when operator config explicitly sets `network: true`.
- Envs are scoped by project and workspace; runner jobs and schedules carry the
  workspace id. Existing static env files can bootstrap the encrypted store once,
  with runner-owned variables removed. Git snapshots and runner archives now strip
  tracked or untracked `.env`/`.env.*` files while retaining `.env.example`, so local
  dotenv files cannot enter Docker build context. The installer creates the runner key but
  deliberately leaves an existing legacy broker/data untouched for rollback.
  Removed obsolete broker code, units, Caddy route, configuration and tests; added
  migration/runbook documentation and advanced SUMMING to 9.3.0.

## Bare bot mentions stay local

- A message containing only the bot's `@mention` in an unbound Telegram topic now
  receives a concise prompt to include a question instead of starting a projectless
  Codex thread and exposing a low-level App Server error.
- The ping is handled before participant quota, volatile context, and the projectless
  worker queue, while substantive mentions and replies keep their existing isolated
  Q&A behavior. Low-level projectless startup/runtime failures remain in server logs and
  are replaced by a concise retry message in Telegram. Added routing and error-boundary
  regressions and advanced SUMMING to 9.2.3.

## Linked-worktree Git metadata remains writable for Project owners

- Owner/editor runs now carry the project-scoped common Git directory alongside the
  conversation worktree in `runtimeWorkspaceRoots` for `thread/start`, `thread/resume`,
  and `turn/start`. This prevents a turn override from silently dropping the linked
  worktree metadata root and blocking `fetch`, commit, or rebase.
- Read-only participant and projectless turns still exclude every Git metadata root.
  Added App Server contract regressions for write/read-only start, resume, and turn
  boundaries, documented the invariant, and advanced SUMMING to 9.2.2.
