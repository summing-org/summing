# 2026-09-05

## Release 9.34.0 — close the ten code-audit findings

- Enforce immutable Project/Workspace/Conversation run scope in viewer history,
  run-diff (including a rebind during the async read), and interrupted-run retry.
  Old prompt, attachment and access payloads cannot follow a rebound topic.
- Stop internal retries of non-idempotent Telegram sends after transport loss,
  malformed success responses or HTTP 5xx. Preserve an explicit uncertain result;
  only confirmed rejections or safe/idempotent methods retain automatic retries.
- Filter tracked working/commit diffs through the same private-path policy as
  direct file reads; use literal pathspecs and disable rename/textconv side paths.
- Make semaphore and workspace-lock waits cancellable. Per-processor cancellation
  exists before admission and workspace preparation, so a deleted queued review
  or cancelled preparation cannot subsequently start a model turn.
- Buffer bounded early detached-review notifications until exact thread/turn ids
  are available. Fail explicitly on buffer overflow or a 30-minute completion
  timeout, attempt interruption, and release runtime resources.
- Fail closed for oversized or NUL-containing text attachments instead of silently
  treating unscanned content as safe.
- Route ODS extraction using the original name/MIME rather than its extensionless
  spool path. Reject unsupported XLS, unreadable sheets and excessive cell repeats.
  Split oversized individual search blocks within the configured chunk limit,
  preserving Unicode boundaries and source block ordinals.
- Move bound/external-topic attachment intake off the shared Telegram poll into
  SQLite: 2 workers, 1 per exact topic, 32 queued events/topic, 256 globally.
  Commands remain responsive; subsequent ordinary messages retain topic order.
  Persist admission and Telegram offset atomically, checkpoint downloaded audio,
  resume on restart and atomically exchange intake for pending agent input.
  Cancel/rebind invalidate late results; ACL is rechecked after transcription.
- Upgrade locked `@xmldom/xmldom` from 0.8.14 to 0.8.15. Registry dependency audit
  reports zero known vulnerabilities; this does not imply absence of code defects.
- Add regression coverage for all ten findings, restart/redelivery, storage failure,
  access revocation and cancellation races. Verify 295 tests, TypeScript checks,
  build and version consistency. Tests use isolated synthetic fixtures and no
  production runner actions, Telegram sends, publication or deployment.

## Select the Codex model independently in every Telegram topic

- Add an official App Server `model/list` client with pagination and normalized
  model/default/reasoning-effort metadata. The runtime no longer has to guess
  which model an empty global `agent.model` selects.
- Persist `model_override` and `effort_override` on the stable Conversation
  identified by the exact `(chatId, topicId)` pair, including a compatible
  migration for existing SQLite databases. Neighboring topics remain
  independent even when they belong to the same SUMMING instance.
- Add `/model`, `/model <model> [effort]`, and `/model default`. Choices are
  validated against the live Codex catalog; invalid model IDs and unsupported
  efforts are rejected without changing the saved selection.
- Resolve the effective model before each editor or read-only run and pass the
  exact model and effort to `turn/start`. A model change made during an active
  run affects only the next run, and both `/model` and `/status` make that
  distinction visible.
- Cover App Server pagination, old-database migration, per-topic isolation,
  command validation, status reporting, editor-turn application, detached
  review application, and Telegram help text.
- Keep repository identity checks scoped to source assets rather than generated
  `.summing-runtime` state, and make the existing concurrent native-media test
  assert the delivery set without depending on nondeterministic completion order.

## Keep production Codex CLI at the Astra-capable baseline

- Pin `0.153.4` as the minimum supported standalone Codex CLI release. This is
  the first stable baseline in the deployment policy that includes the Astra
  model-picker/default fixes needed when `agent.model` is left empty.
- Add a root-only, idempotent `deploy/ensure-codex-version` entry point. It
  validates the repository-owned stable version pin, preserves any newer
  stable installation, downloads the official installer over HTTPS only when
  the managed service-account binary is missing or older, requests the exact
  pinned release non-interactively, verifies the resulting version, and
  repairs `/usr/local/bin/codex` without changing installation method.
- Run the guard during initial activation and atomic deployments after active
  work drains but before the application release switches. Even when the
  application SHA is unchanged, deployment performs a read-only version check;
  an outdated CLI is upgraded and SUMMING alone is restarted and health
  checked, so the dependency invariant can recover without a new code release.
- Cover shell syntax, executable modes, pinning, no-downgrade comparison,
  installer arguments, deployment ordering, and activation integration in the
  deployment asset tests, and document the operator-facing `--check` command.
