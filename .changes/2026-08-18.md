# 2026-08-18

## Team Memory использует отдельную экономичную модель и реже создаёт turns

- Conversation Understanding Loop получил собственные `team_memory.model` и
  `team_memory.effort`; defaults `gpt-5.6-luna`/`low` больше не наследуют модель и
  effort основных Project и projectless coding-turns. Эффективная конфигурация
  публикуется в health, а runtime-regрессия проверяет модель как при создании
  ephemeral thread, так и при запуске structured turn.
- Source-local batching стал спокойнее: trailing quiet window увеличен с 20 до
  60 секунд, hard deadline — с 90 до 300 секунд, event cap — с 40 до 100. Это
  объединяет больше разговорных событий в один model turn, сохраняя немедленный
  запуск заполненного batch и глобальную сериализацию background loops.
- Production/example/fresh-install конфиги, операторская документация и config
  regressions приведены к новым defaults. Версия SUMMING повышена до 9.15.0.

## Codex sandbox читает фактический DNS-конфиг Ubuntu

- Для network-enabled write-turn SUMMING канонизирует `/etc/resolv.conf` и
  добавляет read-доступ только к фактическому regular file. Это покрывает Ubuntu
  с `systemd-resolved`, где публичный путь является symlink на
  `/run/systemd/resolve/stub-resolv.conf`: раньше Landlock видел ссылку, но
  скрывал её цель, поэтому `git pull` мгновенно завершался ложным временным
  DNS-сбоем.
- Read-only и network-disabled профили не получают дополнительного разрешения;
  весь `/run` по-прежнему закрыт. Регрессия проверяет наличие канонического
  resolver path только в сетевом write-профиле.

## Git sandbox, Telegram polling и runner state переживают недоверенный ввод и сбои

- Write-turn больше не может подложить Git hook или execution-конфигурацию:
  Codex sandbox запрещает запись в `hooks`, `config` и `config.worktree`, а
  host-side Git-команды принудительно отключают hooks и fsmonitor. Регрессия
  проверяет, что `post-checkout` не запускается при создании worktree.
- Telegram offset сохраняется только после успешной обработки всего update.
  Временная ошибка больше не теряет сообщение и не пропускает следующие
  updates: проблемный update повторяется в исходном порядке без предварительной
  записи потенциально секретного сырого payload на диск.
- Метаданные runner job записываются через mode-0600 временный файл, `fsync`,
  атомарный `rename` и синхронизацию каталога. Восстановление после рестарта
  использует последнее валидное `job.json`, даже если рядом остался оборванный
  временный файл.

## Deployment сам применяет обновлённые systemd units

- Новый root-only `deploy/sync-systemd-units` атомарно синхронизирует из
  проверенного release allowlist основных SUMMING/deployment units, выполняет
  `daemon-reload` и перезапускает path/timer. Перед заменой helper сохраняет
  временные копии в `/run` и восстанавливает прежние units и расписание при
  любой ошибке.
- Worker запускает sync после успешного health как для нового commit, так и для
  same-SHA repair. Идемпотентный compatibility-вызов из существующего release
  hook позволяет применить механизм уже при первом деплое, который стартовал
  ещё на старой версии worker.
- Регрессии проверяют shell-синтаксис, executable bit, атомарную замену,
  rollback trap, порядок относительно health/commit и отсутствие попытки
  перезапустить выполняющийся `summing-deploy.service`. Версия SUMMING повышена
  до 9.14.1.

## VPS проверяют обновления раз в 30 минут, а «Ход работы» завершает ответ

- `summing-deploy.timer` теперь проверяет `origin/master` каждые 30 минут вместо
  10; ручная кнопка немедленного обновления и атомарный deployment flow не
  изменились.
- Telegram сохраняет аудиотранскрипцию перед финальным ответом, а свёрнутый
  журнал **«Ход работы · …»** размещает в самом конце. Разбиение длинного HTML и
  удаление лишних stream-сообщений продолжают работать для нового порядка.
- Таймер, текст Mini App, эксплуатационная документация и регрессии приведены к
  одному поведению. Версия SUMMING повышена до 9.14.0.

## Все Node recovery secret sources изолированы в deployment-тесте

- Явная зависимость `NodeRecoverySecretSources` теперь охватывает не только
  `config.toml` и `summing.env`, но и MTProto/knowledge-transfer keys, TDLib root
  и repository credentials root. Production defaults не изменились.
- Node recovery test подставляет mode-0600 fixtures для каждого secret source и
  проверяет зашифрованный результат, поэтому непривилегированный
  `summing-builder` больше не пытается читать ни один путь из `/etc/summing`.
- Исправление включено в SUMMING 9.14.0.

## Deployment-тест Node recovery изолирован от production secrets

- Node recovery теперь проверяет наличие свежих Team Space bundles до обхода
  workspaces, чтения secrets и загрузки компонентов. Проверка повторяется перед
  manifest commit, поэтому долгий export по-прежнему замечает изменения Team
  Space во время сборки.
- Пути исходных `config.toml` и `summing.env` стали явной зависимостью
  `NodeRecoveryManager`: production сохраняет прежние безопасные defaults, а
  тест использует собственные mode-0600 fixtures и больше не обращается к
  `/etc/summing/summing.env` от имени непривилегированного deployment builder.
- Регрессия подтверждает, что при отсутствующем Team Space bundle чтение project
  environments не начинается, и что тестовый env действительно попадает в
  зашифрованный secrets-компонент. Версия SUMMING повышена до 9.13.1.

## Admin Mini App отвязывает Project от отдельного Telegram-топика

- В каждой существующей topic binding появилась кнопка **«Отвязать»** с явным
  подтверждением удаления локального Codex-контекста и истории запусков.
- Новый идемпотентный administrator-only `DELETE /api/viewer/admin/bindings`
  валидирует `chat_id + topic_id` и атомарно удаляет Conversation. Запрос
  отклоняется при активном turn, runtime processor или ожидающем input, поэтому
  выполняющаяся работа не может потерять маршрут во время run.
- Удаление каскадно очищает Codex threads, runs и consumed inputs привязки, но
  сохраняет обнаруженные Telegram chat/topic, наблюдаемых пользователей и Team
  Space evidence. Повторная привязка того же топика начинает чистую Conversation
  с прежним детерминированным ID; физический Git worktree автоматически не
  удаляется.
- Добавлены регрессии StateStore, API и Mini App; версия SUMMING повышена до
  9.13.0.

## Node recovery для полного rebuild VPS

- Добавлен отдельный формат `summing-node-recovery` v1, не смешанный с переносимым Team Space: основной SQLite снимается через online backup и очищается от `team_*`, а успешные Team Space export перечисляются в manifest только по object key.
- Recovery разбит на независимо зашифрованные AES-256-GCM/gzip компоненты с SHA-256 каждого файла, HMAC manifest, безопасными archive paths/symlinks и публикацией `manifest.json` последним как commit marker.
- В node bundle входят conversations/runs, runner-control, стабильный node ID, identity/project memory, Codex session JSONL, artifacts, attachments и Git workspaces как repository bundle + staged/working binary patches + untracked. Помимо каталогизированных workspace автоматически обнаруживаются осиротевшие Git repositories/worktrees в managed roots. Generated dependencies/caches и Codex/OAuth auth state исключены; export блокируется, если хотя бы одна текущая Team Space не имеет свежего успешного bundle.
- Опциональный secrets-компонент требует точного `INCLUDE SECRETS`: сохраняет SUMMING config/env/keys, connector-only `core.sqlite`, TDLib session, repository credentials и project environments, полученные через runner. Recovery key показывается один раз, а durable job хранит только envelope под локальным transfer key.
- Добавлены отдельная durable SQLite queue, owner-only Admin API и экран **Система → Node recovery** с export, dry-run, классификацией sessions (`resumable`, `archive_only`, `broken_dependency`), явным подтверждением staging и bounded ошибками.
- Fresh install устанавливает root-команду `restore-node-recovery`: ключ читается скрыто через `/dev/tty`, bundle повторно скачивается и проверяется независимо от app staging, services останавливаются, разрешённые пути восстанавливаются с root-only rollback, а при ошибке выполняется обратное копирование и services остаются остановленными.
- Документирован порядок rebuild: старый VPS нельзя удалять до `succeeded`, сохранения bundle/recovery keys и успешного dry-run. Версия SUMMING повышена до 9.12.0.

## Полная переносимость Team Space

- Заменён source-scoped knowledge bundle на `summing-team-space-transfer` v2: export теперь выбирается по `spaceId` и атомарно снимает SQLite snapshots `state/core` для всех источников пространства.
- В bundle входят Team Space, sources, people/identities, events и revisions, knowledge/evidence/supersessions, consent и unknown-author state, synthesis audit, interventions, project links, checkpoints, content-addressed originals, canonical blocks, chunks и совместимые embeddings.
- Исправлен дефект v1, при котором state-таблицы экспортировались по всему пространству, а core-таблицы — только по одному `source_id`; multi-source round-trip и идемпотентный reimport покрыты тестом.
- Portable bundle получил отдельный случайный recovery key. Durable job хранит только AES-256-GCM envelope под локальным `kb-transfer.key`; raw key показывается администратору один раз и переносится на другую VPS без копирования серверного master key.
- Import проверяет HMAC, AES-GCM, checksums, catalog metadata и полный source manifest, выполняет dry-run конфликтов, сохраняет локальные consent revokes и пересобирает производный search index.
- Admin Mini App теперь выбирает Team Space, показывает число sources/project dependencies, принимает recovery key для import и выводит импортированные источники, которым требуется локальный MTProto connector и идемпотентный reconciliation backfill.
- Связанные project IDs переносятся как явные зависимости. Репозитории, worktree, Codex authorization, Bot API/MTProto credentials, operational queues и node configuration остаются ресурсами ноды и не копируются в Team Space bundle.
- Версия SUMMING повышена до 9.11.0.
