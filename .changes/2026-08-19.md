# 2026-08-19

## Project runner читает release без доступа к секретной группе приложения

- Host installer устанавливает POSIX ACL и выдаёт отдельной группе
  `summing-project-runner` только read/execute-доступ к immutable release. Runner
  не добавляется в группу `summing` и по-прежнему не может читать секреты
  приложения в `/etc/summing`.
- Перед запуском сервиса installer проверяет фактическую читаемость скомпилированной
  точки входа от имени runner-пользователя. Это предотвращает цикл systemd
  restart с маскирующей настоящую причину ошибкой `MODULE_NOT_FOUND`.

## Управляемые проекты автоматически получают изолированный runner

- Создание и клонирование managed-проекта теперь сразу регистрирует его в
  project runner. При временной недоступности socket регистрация повторяется в
  фоне, а после рестарта сервиса каталог сверяется целиком, поэтому привязка
  проекта к топику больше не зависит от ручной подготовки runner-конфига.
- Runner хранит только ограниченные сервером профили проекта: идентификатор,
  разрешённые workspace, безопасные пути конфигурации и вычисленный data root.
  Клиент не может передать image, registry, произвольный host path или ослабить
  сетевые ограничения; профили сохраняются атомарно и переживают рестарт.
- Project runner вынесен из старого внешнего namespace в отдельные
  `summing-project-runner.service`, системного пользователя, Unix socket и
  каталоги. Идемпотентный host installer поднимает rootless Docker, проверяет
  socket до переключения приложения и сохраняет пользовательский override.
- Deploy, rollback, fresh-install и recovery используют новый namespace; тесты
  покрывают регистрацию, повторные попытки, восстановление, workspace
  isolation, защиту профилей и запрет подмены внешнего `summing-runner.service`.

## Telegram-агент использует тот же managed deploy key, что и Mini App

- В write-turn добавлен host-side namespace `repository`: свежий `inspect`
  выполняет fetch, `verify_access` проверяет чтение и dry-run записи, `pull`
  допускает только fast-forward, а `push` публикует только текущую ветку без
  force. Агенту явно запрещено определять состояние origin по устаревшим refs
  или выполнять сетевые Git-команды напрямую из sandbox.
- Все операции проходят через существующий `GitInspector` и managed credential
  хоста. Приватный ключ и его filesystem-пути не попадают ни в sandbox, ни в
  tool result; project, workspace, repository path, actor и текущий turn
  фиксируются доверенным runtime, а stale HEAD, dirty/diverged state и
  небезопасная Git-конфигурация отклоняются прежними проверками Mini App.
- Agent и Mini App разделяют один repository-operation lock. Старые write
  threads один раз архивируются при переходе на новый capability marker, чтобы
  App Server не восстановил сохранённый набор dynamic tools без `repository`.
  Регрессии покрывают dispatch-контракт, owner/turn isolation, отсутствие
  credential metadata в ответе и полный host-side цикл verify/fetch/pull/push.
