# 2026-08-17

## Telegram Team Spaces have a permanent, consent-gated knowledge library

- Added persistent TDLib/MTProto connectors alongside Bot API ingestion. A
  connector keeps only its encrypted authorization state, can serve several
  allowlisted groups, resumes checkpointed backfills, tails new/edit/delete
  events, never imports unrelated chats, and can be revoked only after every
  source is unbound. API hashes and sessions use AES-256-GCM with a separately
  provisioned master key and per-connector HKDF-derived TDLib keys; codes and
  2FA passwords remain memory-only challenges.
- Added `core.sqlite` sync metadata for connectors, source bindings, consent,
  runs/checkpoints, revisions, durable jobs, notification outbox, content
  objects, canonical blocks, chunk manifests, embeddings, and universal
  evidence. Existing Team Space events intentionally remain in the established
  `state.sqlite3` store for an online-compatible rollout; a future offline
  migration can consolidate that table without risking production WAL loss.
- Added S3-compatible content-addressed object storage with SHA-256
  deduplication, AES256/KMS server-side encryption, bounded local spooling, and
  local storage only for development/tests. Media upload, extraction, FTS,
  embeddings, and knowledge synthesis are independent retryable stages, so a
  completed Telegram history does not depend on S3 or model availability.
- Added canonical PDF, DOCX, XLSX/ODS, PPTX, image, audio, and video extraction.
  Pages/slides/sheets, coordinates, tables, formulas, cached values, media, OCR,
  captions, and transcripts retain structural provenance; Markdown is never the
  source of truth or a second indexed text copy. Model enrichment is checked
  against the author's active `model_egress` consent immediately before egress.
- Added contentless FTS5 plus isolated `VectorIndex`/`sqlite-vec` search,
  structural chunk deduplication, versioned `text-embedding-3-small` vectors,
  resumable index reconstruction, top-40 lexical/vector reciprocal-rank fusion,
  filters, neighboring canonical blocks, and bounded evidence-backed context
  packs. Raw messages are searchable through FTS but are not embedded.
- Added idempotent first-sync completion notifications through a transactional
  outbox, owner-private `/sync_status` overview/detail commands, and owner-only
  Admin Mini App flows for MTProto authorization, consent, start/pause/resume,
  unbind, diagnostics, and confirmed connector logout. Unknown or unconsented
  authors are discarded before persistence; consent revocation cascades through
  messages, object references, derived search data, and affected knowledge while
  preserving still-referenced shared objects.
- Added release gates for Telegram terms review, production S3, protected-content
  groups, strict MTProto key handling, idempotent Bot API/MTProto event identity,
  first-notification exactly-once behavior, shared-object deletion, extractor
  fidelity, search-index versioning, private command access, and Admin API
  authorization. The complete suite passes with 160 tests and the dependency
  audit reports no vulnerabilities.

## Runner jobs recover, deduplicate, and report their outcome

- On runner startup, persisted `queued`, `running`, and `cancelling` jobs now
  become terminal `interrupted` jobs with a completion timestamp, an explicit
  recovery log entry, and no automatic restart. Interrupted jobs participate in
  normal terminal retention and appear as a distinct diagnostic status.
- Agent and schedule submissions now carry a host-derived SHA-256 idempotency
  key. The runner coalesces concurrent requests, returns an already accepted job
  for later retries, and rejects reuse for a different action or trigger; the
  control plane also avoids rebuilding a source snapshot when the same dynamic
  tool call is delivered again.
- `runner.inspect` now includes a compact host-generated overview with idle,
  queued, running, or unavailable state, counts, the nearest enabled schedule,
  and the last result. Manual jobs are durably watched in the control database;
  completion, cancellation, interruption, or failure is delivered once to the
  originating Telegram topic, while existing schedule failure routing remains
  unchanged. Advanced SUMMING to 9.9.1.

## Owners manage runner jobs, schedules, and artifacts through the agent

- Added a host-defined, conversation-scoped `runner` tool namespace to Codex App
  Server threads. Owners can ask natural-language status questions backed by live
  active/queued/recent jobs, schedule executions, and artifact availability, then
  read a bounded untrusted job-log tail and explicitly start or cancel a fixed
  runner action without exposing Project,
  Workspace, actor, repository path, Docker, systemd, or filesystem scope as model
  arguments.
- Added durable daily/weekly schedules with IANA time zones, ISO weekdays,
  current-`master` revision resolution, occurrence deduplication, overlap skipping,
  bounded misfire grace, execution reconciliation, owner failure notifications,
  audit records, and two-turn confirmation for create/update/delete. The control
  plane is Project-generic: it does not infer or embed any external customer
  Project ID or import project-specific cron/systemd units by name.
- Removed Build/Validate/Dry/Live launch controls from Project Viewer. **Раннер**
  is now a diagnostic jobs/logs/artifacts screen with the previously authorized
  emergency cancellation control; schedules and normal launches remain agent-first.
- Added bounded artifact listing/reading and two-turn delete/clear plans that freeze
  exact `jobId/name` targets. The isolated runner validates the Project/Workspace,
  dry-run job, allowlisted regular file, moves confirmed files into private trash,
  updates `artifactCount`, reports partial failures, and never includes artifacts
  created after a cleanup plan.
- Added lazy one-time migration for existing editor conversations: a write thread
  without `runner-control-v1` is archived to `previous_codex_thread_id`, then a new
  tool-capable thread is started. Read-only participant threads are unchanged.
- Added App Server dynamic-tool protocol coverage, scheduler/time-zone
  coverage, artifact confirmation and frozen-target coverage, thread migration,
  Viewer contracts, runner cancellation/artifact integration, and deployment asset
  regression checks. Advanced SUMMING to 9.9.0.

## Runner jobs can be stopped from a clearer Project Viewer

- Added authenticated cancellation across Project Viewer, the runner client,
  and the isolated runner server. Queued jobs are removed and finalized without
  execution; running jobs move through `cancelling` to `cancelled`, interrupt
  the active command, and force-remove only their UUID-derived container.
- Added cancellation timestamps, terminal retention, bounded command shutdown,
  idempotent repeated cancellation, live UI status polling after a stop request,
  and regression coverage for queued/running cancellation and viewer scoping.
- Renamed the ambiguous Project Viewer tabs: **Правки агента** now means Codex
  before/after patches, while **Раннер** contains Build, Validate, Dry run, Live
  run, logs, artifacts, and the new **Остановить** action. Advanced SUMMING to
  9.8.9.

## Telegram images reach the agent as visual input

- Added ingestion of Telegram `photo` messages using the largest available size,
  while image documents are now distinguished from opaque documents throughout
  the pending-input and workspace materialization pipeline.
- Added bounded HEIC/HEIF-to-JPEG conversion in a worker thread so iPhone files
  have a model-compatible representation without host image packages.
- Added native Codex App Server `localImage` turn inputs for materialized images,
  with regression coverage for Telegram recognition, conversion, state restore,
  runtime delivery, and protocol payloads. Advanced SUMMING to 9.8.8.

## Editor runs deliver generated files to Telegram

- Added a per-conversation `.summing-runtime/outbox` that is cleared before each
  run and writable only by the editor permission profile. Runtime context now
  tells Codex to place final deliverables there instead of presenting VPS paths
  as external links.
- Added bounded, symlink-safe outbox collection: SUMMING accepts at most ten
  regular single-link files within the configured aggregate byte limit, opens
  them with `O_NOFOLLOW`, and reports rejected or failed uploads without changing
  an otherwise successful Codex run.
- Added multipart Telegram `sendDocument` delivery after successful turns,
  preserving the originating chat, topic, and reply. Covered the transport,
  sandbox profile, outbox boundary, and complete editor-run delivery path with
  automated tests, and advanced SUMMING to 9.8.7.
