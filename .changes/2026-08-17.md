# 2026-08-17

## MTProto authorization reaches Telegram before asking for an OTP

- Encode the per-connector TDLib database encryption key as padded standard
  base64, matching TDLib's JSON `bytes` contract and preventing authorization
  from closing with `Wrong padding length` before Telegram can send a code.
- Start authorization challenges in an explicit `starting` state and expose
  `wait_code` only after TDLib invokes `getAuthCode`, so the Admin Mini App no
  longer claims that Telegram sent a code before the request completed.
- Added regression coverage for the 32-byte padded database key, the initial
  authorization API state, and the corrected Mini App status message.

## Fresh bootstrap preserves Caddy and SSH configuration semantics

- Validate generated Caddyfiles explicitly with the `caddyfile` adapter before
  installing them, matching the adapter selected by the Caddy systemd unit.
- Resolve the real source `HostName` through the operator's local SSH config and
  carry that bounded value into the VPS deploy-key config, so repository aliases
  remain usable by unattended self-updates without copying unrelated SSH config.
- Normalize an existing `summing` service account to `/var/lib/summing` with a
  `nologin` shell during both cloud-init and SSH provisioning. This ensures
  OpenSSH reads the isolated deploy-key config even when the base image already
  supplied an account with the same name.
- Create Caddy candidates and bounded installation summaries at unique `/run`
  paths and remove them with the guarded exit cleanup after success or failure.
- Added installer regression assertions for the Caddy adapter, SSH alias mapping,
  and service-account identity invariants.

## Fresh bootstrap clones verified bundles without widening installer input access

- Keep the uploaded release bundle and its root-only input directory private,
  while staging a mode-0600 copy owned by the unprivileged `summing` runtime
  identity inside the disposable bundle-verification directory.
- Clone only from that verified staging copy, then remove the copy and verifier
  with the existing guarded exit cleanup. This allows first installation from a
  root-uploaded bundle without making the manifest or source key traversable.
- Added regression assertions for the staged bundle ownership and unprivileged
  clone path.

## Team Spaces can be exported and restored without MTProto secrets

- Added durable owner-only knowledge-transfer jobs and Admin Mini App controls
  for `manifest` and `portable` exports, import dry-runs, explicit consent
  confirmation, bounded errors, restart recovery, and transfer status. Bundles
  contain Team Space evidence, knowledge, canonical objects/blocks/chunks, and
  compatible embeddings, but never contain conversations, connector settings,
  TDLib sessions, API credentials, authoritative sync runs, ingestion queues,
  or the notification outbox. The latest cursor is retained only as an
  informational import hint and is never used to resume MTProto by itself.
- Each export uses online SQLite backups to build a sanitized versioned catalog.
  The catalog is gzip-compressed, AES-256-GCM encrypted, checksummed, and covered
  by a canonical HMAC manifest uploaded last as the bundle commit marker. A
  separately provisioned `/etc/summing/kb-transfer.key` is generated by the VPS
  activation script and must be transferred out-of-band to a replacement server.
- `manifest` mode references verified canonical S3 objects without duplicating
  them. `portable` mode encrypts and copies every unique SHA-256 object into the
  export prefix with a distinct nonce, making a copied prefix self-contained.
  Temporary backups, clear catalogs, and per-object files remain inside the
  configured private spool, are checked against its byte limit, and are removed
  after each operation.
- Import now verifies the manifest signature, encrypted catalog checksum, GCM
  tags, SQLite integrity, per-object hashes and sizes, then reports conflicts and
  missing objects without mutating either database. Confirmed imports preserve
  stable provider identities, remap integer evidence/block/chunk IDs, reuse
  existing records idempotently, retain local consent revocations, redact any
  affected imported evidence, and rebuild the derived FTS/sqlite-vec index.
- Added production/example configuration, deployment key provisioning, runbook
  guidance, Admin API coverage, manifest and portable round-trips, tamper
  rejection, clean-database restore, repeated-import, local-revoke, search-reset,
  and installer regression tests. Advanced SUMMING to 9.10.0.

## Telegram Team Spaces have a permanent, consent-gated knowledge library

  connector keeps only its encrypted authorization state, can serve several
  allowlisted groups, resumes checkpointed backfills, tails new/edit/delete
  events, never imports unrelated chats, and can be revoked only after every
  source is unbound. API hashes and sessions use AES-256-GCM with a separately
  provisioned master key and per-connector HKDF-derived TDLib keys; codes and
  2FA passwords remain memory-only challenges.
- Added `core.sqlite` sync metadata for connectors, source bindings, consent,
  runs/checkpoints, revisions, durable jobs, notification outbox, content
  objects, canonical blocks, chunk manifests, embeddings, and universal
  evidence. Existing Team Space events intentionally remain in the established
  `state.sqlite3` store for an online-compatible rollout; a future offline
  migration can consolidate that table without risking production WAL loss.
- Added S3-compatible content-addressed object storage with SHA-256
  deduplication, AES256/KMS server-side encryption, bounded local spooling, and
  local storage only for development/tests. Media upload, extraction, FTS,
  embeddings, and knowledge synthesis are independent retryable stages, so a
  completed Telegram history does not depend on S3 or model availability.
- Added canonical PDF, DOCX, XLSX/ODS, PPTX, image, audio, and video extraction.
  Pages/slides/sheets, coordinates, tables, formulas, cached values, media, OCR,
  captions, and transcripts retain structural provenance; Markdown is never the

- Added contentless FTS5 plus isolated `VectorIndex`/`sqlite-vec` search,

  resumable index reconstruction, top-40 lexical/vector reciprocal-rank fusion,

- Added idempotent first-sync completion notifications through a transactional

  messages, object references, derived search data, and affected knowledge while

- Added release gates for Telegram terms review, production S3, protected-content
  groups, strict MTProto key handling, idempotent Bot API/MTProto event identity,

## Runner jobs recover, deduplicate, and report their outcome

- On runner startup, persisted `queued`, `running`, and `cancelling` jobs now
  become terminal `interrupted` jobs with a completion timestamp, an explicit
  recovery log entry, and no automatic restart. Interrupted jobs participate in
  normal terminal retention and appear as a distinct diagnostic status.
- Agent and schedule submissions now carry a host-derived SHA-256 idempotency
  key. The runner coalesces concurrent requests, returns an already accepted job
  for later retries, and rejects reuse for a different action or trigger; the
  control plane also avoids rebuilding a source snapshot when the same dynamic
  tool call is delivered again.
- `runner.inspect` now includes a compact host-generated overview with idle,
  queued, running, or unavailable state, counts, the nearest enabled schedule,
  and the last result. Manual jobs are durably watched in the control database;
  completion, cancellation, interruption, or failure is delivered once to the
  originating Telegram topic, while existing schedule failure routing remains
  unchanged. Advanced SUMMING to 9.9.1.
