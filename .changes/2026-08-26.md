# 2026-08-26

## Restart-safe runs, assurance evidence, detached review, scoped history, and structured memory

- Direct response and document delivery is now a durable per-run obligation committed
  atomically with the run result. Stream message IDs and staged document checksums
  survive process failure; ambiguous Telegram outcomes become `uncertain` and are never
  resent automatically. Interrupted write runs require `/retry <run_id>` and retain retry
  lineage; safe read-only runs replay only before Telegram accepts a message.
- Codex command completions now produce local run evidence: status, exit code, duration,
  digests, bounded secret-redacted output, conservative `current`/`stale`/`unknown`
  freshness, and explicit `scope: unknown`. Viewer exposes aggregates only.
- `/review` now uses the official detached `review/start` flow from a read-only source
  thread, persists findings, and compares before/after Git snapshots. Any reviewer
  mutation invalidates the review.
- Project/Workspace-scoped FTS history indexes original requests and final responses but
  not augmented prompts. `project_history` host tools return only metadata, digests, and
  assurance data; historical message text stays local.
- Project memory is structured with kinds, lifecycle, provenance, and deduplication.
  Existing `memory.md` remains a legacy backup, the database projection is written to
  `memory.structured.md`, direct file edits are rejected and preserved, and
  `/remember_*` plus `project_memory` tools manage it.
- Recovery includes state and run artifacts; startup is fail-closed and never drains
  dormant delivery payloads.
- Verification covers Node 24 lint/build and the full 226/226 test suite, including
  migration, restart, ambiguous-delivery, and reviewer-mutation scenarios.

## Quiet service outbox directories and preserve video MIME types

- Outbox collection now silently ignores only empty top-level `.agents` and `.codex`
  directories created by the Codex runtime. Non-empty directories, symlinks, and every
  other non-file entry continue to produce the existing safety warning.
- MP4 files collected from the runtime outbox or attached through Project portal are now
  labelled `video/mp4` instead of the generic `application/octet-stream` MIME type.
- Workspace tests cover empty-directory suppression, rejection visibility for a non-empty
  service directory, and MP4 MIME detection.

## Project primary/observer topology replaces the user-facing portal bridge

- Conversation bindings now expose the domain role `primary | observer`. The SQLite
  storage value `external-readonly` remains a compatibility detail and is read as
  `observer`, so existing nodes upgrade without a destructive table migration.
- Each Project/Workspace accepts one primary working topic and any number of observers.
  Primary is the only owner/editor authority; observer is read-only even when the sender
  is an administrator or Project owner.
- Admin Mini App and `/bind_observer_topic` bind observers without `portalKey` or default
  route configuration. `/bind_external_topic` remains a hidden compatibility alias for
  existing automation. Binding notices explain the office-table authority boundary.
- `/publish <обновление>` lets an owner explicitly broadcast one safe text update from
  primary to every observer of the current Workspace. Each destination gets its own
  idempotent durable outbox record; automatic runner artifacts are not broadened to all
  observers and continue to require their configured legacy route.
- Observer messages remain source-local Team Space evidence. Up to 20 recent
  consent-visible comments are added to the next primary owner-run as untrusted feedback;
  bot-authored published updates are excluded from that feedback view. Observer Q&A sees
  its own published updates and topic history, while comments are never promoted to
  requirements, decisions, approval, or actions without explicit owner direction.
- A Git observer worktree now fast-forwards to the published source-checkout `HEAD` before
  Q&A. Dirty, ahead, or divergent snapshots fail closed instead of exposing a stale or
  private observer branch.
- The portal outbox, encrypted inbound artifacts, targeted replies, and legacy runner
  routes remain internal reliability infrastructure. User-facing documentation and UI now
  describe observer delivery rather than transport routes.

Verification covers role cardinality, observer feedback visibility, explicit publication,
Admin binding/API behavior, help text, and observer snapshot fast-forwarding under Node 24.
