# 2026-08-22

## Внешний Project portal стал универсальным транспортом сообщений

- Внутренний авторизованный Project-агент получил host-scoped namespace
  `project_portal`: он перечисляет привязанные внешние топики, читает их общую
  долговечную историю и по явной просьбе владельца отправляет текст или один
  безопасный файл. Файл можно взять из workspace проекта, ранее полученного
  вложения или другого Project-материала; транспорт больше не ограничен
  специальными runner-артефактами.
- Исходящие сообщения проходят через постоянную filesystem outbox с точным
  Project/Workspace/portal scope, idempotency key, SHA-256 вложения, повторной
  проверкой активной привязки и bounded retry. После рестарта незавершённая
  доставка продолжается, а outbox включена в node recovery. Telegram-токен и
  произвольные host paths агенту и project-контейнеру не передаются.
- Runner больше не знает о `REPORT_CHAT_ID` / `REPORT_THREAD_ID` и специальном
  `report-request.json`. Любой проект может оставить bounded
  `portal-messages.json` с текстами и документами; SUMMING маршрутизирует их
  через тот же Project portal outbox. Адаптер `ash-telegrams` переведён на этот
  общий контракт для отправки `report.html`.
- Комментарии заказчика по-прежнему являются обычными событиями общей истории
  портала: они доступны агенту для Q&A и анализа, но сами не одобряют план, не
  меняют ТЗ и не запускают публикацию.
