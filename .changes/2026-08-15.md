# 2026-08-15

## Owner and admin can fast-forward a reviewed HEAD into origin/master

- Added a separate Project Viewer action that previews `origin/master`, the exact
  current `HEAD` and the number of commits, then asks for explicit confirmation before
  publishing. Existing Push keeps its original same-name remote-branch semantics.
- Re-fetches origin and compares both expected full SHAs, requires a clean worktree and
  an existing `origin/master`, and accepts only an ancestry-proven non-force fast-forward.
  It never creates the main branch, merge commits, rebases, resets or rewrites history.
- Applied the existing owner/admin ACL, active-run serialization, managed-key write gate
  and repository audit to the new action; added dirty, stale-origin, divergence, hook,
  confirmation and role coverage, documented the contract and advanced SUMMING to 9.5.4.

## Direct Telegram replies recover their bounded ancestor chain

- Extended host-built direct reply context from one Telegram `reply_to_message` to a
  bounded chain of up to eight messages. The immediate parent remains authoritative
  from the current Bot API update; older ancestors are resolved only within the same
  Team Space Source through durable `reply_to_external_event_id` evidence links.
- Kept the chain safe and explainable: cycles, missing or redacted evidence stop
  traversal, every recovered text is checked again for credential-like content, and
  each quote retains depth, message and sender identity plus attachment presence.
  The prompt now explicitly follows referential bridges such as «вот», «это» and
  «сюда» to the deepest relevant quoted message instead of treating the bridge as
  the whole request.
- Added a bound-topic regression for `@mention → «вот» → substantive decision`,
  integrated the behavior with the unified Conversation Understanding Loop,
  documented the transport invariant, and advanced SUMMING to 9.5.4.

## Deploy migration bootstraps its own network gate without unbounded job history

- Closed the legacy environment cutover bootstrap loop: when an imported migration
  still needs verification, the root-only hook now reads the immutable release project
  config and atomically enables only an explicitly declared `network: true` while
  preserving legacy `envPath`. The running coordinator can then complete Validate and
  Dry run before the next deploy tick performs the existing transactional cutover.
- Represented the expected two-tick interval as deploy `waiting` with a successful
  oneshot exit instead of a false `failed`; malformed config, marker, schedule, key,
  runner or Caddy state still fails closed. On startup and after each completion,
  runner job directories are now bounded to the latest 100 terminal jobs per Project
  without deleting queued/running or malformed operator state; detailed Dry run
  artifacts retain their separate limit of 30.
- Added deployment-asset and runner-retention regressions, documented the operational
  contract and advanced SUMMING to 9.5.3.

## Render agent Markdown natively in Telegram

- Added a dependency-free Markdown → Telegram HTML boundary for direct Project replies,
  projectless Q&A and gated Conversation Understanding interventions. Headings, lists,
  task items, emphasis, spoilers, safe links, quotes, inline/fenced code and tables now
  render in Telegram instead of arriving as literal Markdown syntax.
- Raw model HTML is escaped, unsupported/dangerous link schemes are never emitted as
  clickable links, and Telegram receives `parse_mode=HTML` for both initial sends and
  streaming edits. Runtime/audit persistence continues to keep the original Markdown.
- Replaced plain-text response splitting with entity-aware HTML chunking. Each long-message
  chunk is independently balanced, preserves formatting across boundaries and stays below
  the Telegram payload safety margin.
- Added renderer, streaming and API contract coverage, documented the delivery invariant,
  and bumped SUMMING to `9.5.2`.

## Editor sandboxes can commit linked worktrees and run the Node toolchain

- Preserved both halves of linked-worktree Git metadata across every Codex thread and
  turn: the repository common directory and the resolved per-worktree Git directory.
  The write profile now grants each exact path separately, so Codex's recursive
  protection of the `.git` pointer target no longer leaves `index.lock` read-only while
  metadata from unrelated repositories remains outside the profile.
- Exposed the installed Node.js runtime to editor sandboxes without hardcoding a VPS
  version. SUMMING resolves the installation root from `process.execPath` and grants it
  read-only access, allowing versioned `/opt/node-v*/` targets behind `node`, `npm`, `npx`
  and `corepack` symlinks while keeping the participant profile unchanged.
- Added coordinator and permission-profile regressions for the common/resolved Git roots,
  Node installation visibility and guest isolation; updated the architecture contract and
  advanced SUMMING to 9.5.1.
