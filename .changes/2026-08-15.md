# 2026-08-15

## Render agent Markdown natively in Telegram

- Added a dependency-free Markdown → Telegram HTML boundary for direct Project replies,
  projectless Q&A and gated Conversation Understanding interventions. Headings, lists,
  task items, emphasis, spoilers, safe links, quotes, inline/fenced code and tables now
  render in Telegram instead of arriving as literal Markdown syntax.
- Raw model HTML is escaped, unsupported/dangerous link schemes are never emitted as
  clickable links, and Telegram receives `parse_mode=HTML` for both initial sends and
  streaming edits. Runtime/audit persistence continues to keep the original Markdown.
- Replaced plain-text response splitting with entity-aware HTML chunking. Each long-message
  chunk is independently balanced, preserves formatting across boundaries and stays below
  the Telegram payload safety margin.
- Added renderer, streaming and API contract coverage, documented the delivery invariant,
  and bumped SUMMING to `9.5.2`.

## Editor sandboxes can commit linked worktrees and run the Node toolchain

- Preserved both halves of linked-worktree Git metadata across every Codex thread and
  turn: the repository common directory and the resolved per-worktree Git directory.
  The write profile now grants each exact path separately, so Codex's recursive
  protection of the `.git` pointer target no longer leaves `index.lock` read-only while
  metadata from unrelated repositories remains outside the profile.
- Exposed the installed Node.js runtime to editor sandboxes without hardcoding a VPS
  version. SUMMING resolves the installation root from `process.execPath` and grants it
  read-only access, allowing versioned `/opt/node-v*/` targets behind `node`, `npm`, `npx`
  and `corepack` symlinks while keeping the participant profile unchanged.
- Added coordinator and permission-profile regressions for the common/resolved Git roots,
  Node installation visibility and guest isolation; updated the architecture contract and
  advanced SUMMING to 9.5.1.
