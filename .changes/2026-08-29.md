# 2026-08-29

## Release 9.29.0

- Advanced SUMMING from `9.28.0` to `9.29.0` for condition-aware runner report
  delivery and owner-authorized result replies.

## Deliver explicit reports by outcome for dry-run and live-run

- Scheduled `dry-run` and `run` plans now share exact Telegram topic delivery and
  persist a `deliveryCondition` of `success`, `failure`, or `always`; existing
  schedules migrate to the fail-closed-compatible `success` default.
- Runner capture now processes bounded artifacts and `portal-messages.json` before
  converting a non-zero workload exit into a failed job. A partial run can therefore
  declare a detailed failure report and deliver it under `failure` or `always`, while
  absence of the manifest still means no external delivery.
- Added regression coverage for failed live-run manifest capture, schedule migration,
  live-run outcome filtering, and exact destination handoff.

## Send only into an owner-selected result discussion

- Extended `project_context` with `results` and `send`: the agent must resolve one
  concrete `resultId`, and send is accepted only from the matching active authorized
  owner turn and Project/Workspace.
- The host derives the customer channel, Telegram topic, and default reply target from
  the publication index. An optional reply target must already belong to the same
  discussion, so the model cannot supply an arbitrary destination or fan out.
- Text and up to ten safe workspace files pass through the existing durable outbox with
  idempotency, retries, dead-letter and uncertain-delivery behavior. Sent messages are
  indexed back into the selected result discussion so later replies remain scoped.
