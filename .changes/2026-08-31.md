# 2026-08-31

## Release 9.30.0

- Advanced SUMMING from `9.29.0` to `9.30.0` for owner-scoped, persistent
  multi-topic Project portals.

## Send arbitrary messages to exact external portal topics

- Restored `project_portal` as an active write-thread host namespace. An owner can
  list stable Project/Workspace routes, read bounded consent-visible history, and
  send text or up to ten safe files to one mandatory `portalKey` without supplying
  raw Telegram IDs or a reply target.
- Active-turn owner, Project and Workspace scope are checked by the host. Delivery
  uses the existing durable outbox with idempotency, retry, dead-letter and
  uncertain-delivery safeguards; repeats remain idempotent even when the first send
  creates the route's Team Source record.
- Admin → Telegram now binds any number of external topics as `Portal` routes with
  unique logical keys alongside the single primary working topic.

## Receive portal evidence without activating an external agent

- A bound portal topic records available messages and encrypted inbound attachments
  without requiring a reply or `@mention`. The owner can later search this history
  or materialize an attachment from the primary Project turn.
- Portal content remains untrusted evidence and never becomes authorization,
  requirements or Project instructions. Portal topics do not start Codex processors
  and do not answer automatically, including when a participant mentions or replies
  to the bot.
- Kept result-scoped `project_context.send(resultId)` and scheduled
  `portal-messages.json` delivery as separate stricter workflows.
