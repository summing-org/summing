# 2026-08-13

## Auditable snapshot waiver for host migration

- Added an explicit `SUMMING_SNAPSHOT_WAIVED=1` apply mode for operators who
  intentionally accept migration without an external VPS snapshot. It is
  mutually exclusive with `SUMMING_BACKUP_CONFIRMED=1`, so the tool never asks
  an operator to make a false backup assertion.
- Both modes still stop services before capturing the server-local recovery
  bundle; its manifest now records `backup_mode`. Failure guidance distinguishes
  snapshot restoration from the riskier manual bundle-only recovery path.
- Updated the README, operations handbook, and deployment invariant tests to
  document and enforce the honest waiver contract.

## Guarded 8.x host migration to SUMMING 9.0

- Added an executable `deploy/migrate-host-to-summing` with a read-only
  `--check` mode and a snapshot-gated `--apply` mode. Preflight refuses active
  Codex runs, an active deploy worker, dirty source state, conflicting target
  users/paths/project IDs/branches/runtime directories, an unhealthy enabled
  runner, or a new GitHub remote that the existing deploy key cannot read.
- Apply stops polling and timers before copying a root-only recovery bundle with
  manifest, configuration, a consistent SQLite backup, old units, current link,
  and releases. It preserves UID/GID while renaming application, builder, and
  runner accounts; moves durable/config/repository paths; updates only
  operational configuration and secrets-file keys; relinks Codex; and keeps the
  preserved release artifacts recoverable rather than deleting them.
- Migrates stored self-project IDs/names and absolute paths transactionally,
  repairs linked Git metadata, renames conversation branches and reserved
  runtime directories without touching uncommitted files, refreshes identity
  and context assets, retags rootless Docker build images, installs only SUMMING
  units, runs the standard activation pipeline, and verifies application and
  runner health.
- Documented the required publish → GitHub repository rename → VPS snapshot →
  checkout fast-forward → preflight → apply sequence in both the README and
  Russian operations handbook. Added executable/syntax and safety invariant
  tests, including explicit rejection of recursive deletion in the migration.

## One SUMMING identity

- Consolidated the company, product, Telegram agent, Viewer, runtime prompts,
  documentation, package metadata, Git identity, and deployment messages under
  the single uppercase public identity **SUMMING**; the former product and
  platform identities no longer appear in product assets.
- Renamed every technical namespace consistently: npm package, `SUMMING_*`
  environment variables, `.summing-runtime`, `summing/*` conversation branches,
  Unix users, durable directories, sockets, container labels, systemd units,
  deployment assets, release metadata, and the expected
  `summing-org/summing.git` repository URL.
- Advanced the major version to 9.0.0 because the host paths and service names
  intentionally form a new deployment boundary. Existing 8.x hosts must be
  migrated deliberately before enabling the new units; a blind automatic
  update is expected to fail health checks and roll back safely.
- On the first workspace preparation, default durable identity files, existing
  conversation branches, hidden runtime directories, and Git exclude entries
  are upgraded in place to SUMMING while preserving runtime files and
  uncommitted workspace changes.
- Added a repository-wide identity invariant test that scans maintained product
  assets and filenames, so neither retired identity can be reintroduced while
  package and runtime version assertions keep the 9.0 boundary explicit.

## VPS Codex usage in Telegram

- Added administrator-only `/limits`, backed by the VPS process's official
  `account/rateLimits/read` App Server RPC, so the displayed five-hour and
  weekly windows come from the server's dedicated `CODEX_HOME` rather than a
  developer laptop.
- Added a 15-minute and event-driven refresh loop that publishes the weekly
  remaining percentage and reset time through Telegram
  `setMyShortDescription`; unauthenticated and unavailable weekly states remain
  explicit instead of substituting a shorter quota window.
- Added validated `[codex_usage]` profile, interval, and IANA-timezone settings,
  exposed the weekly snapshot in loopback health state, covered parsing,
  transport, command access, and configuration with tests, documented VPS
  behavior, and advanced SUMMING to 8.7.0.

## Repeatable deployment activation

- Activated the ten-minute origin deployment timer and administrator-triggered
  path unit on the production VPS, then verified the worker's idle state against
  the exact published revision and both application and isolated-runner health.
- Fixed repeated `deploy/activate.sh` runs so the runner systemd unit substitutes
  the real `summing-runner` UID instead of installing the `RUNNER_UID` template
  literally; added a regression assertion and advanced SUMMING to 8.6.1.

## Atomic origin deployment and administrator update settings

- Added one serialized deployment worker shared by a ten-minute systemd timer
  and a manual Project Viewer request watched through `systemd.path`; no public
  webhook endpoint or GitHub-hosted SSH credential is required.
- Production now builds exact `origin/master` snapshots in versioned release
  directories and atomically switches `/opt/summing-current`. The mutable
  `/opt/summing` self-change repository is fetched without pull, reset, checkout,
  index, or working-tree mutation.
- Deployments reject an unexpected pinned remote and non-fast-forward history,
  wait for active Codex runs to drain, restart both SUMMING and the isolated
  runner, verify their loopback health endpoints, and automatically restore the
  prior release when the new version fails.
- Builds run under a dedicated `summing-builder` account that cannot read the
  application environment or data directory. The deployment service does not
  load `/etc/summing/summing.env`, so npm lifecycle and test processes do not
  inherit Telegram, OpenAI, or Groq credentials.
- Added an administrator-only **Настройки** section to the Telegram Mini App with
  deployed/remote revisions, deployment phase, last check, and an
  **Обновиться сейчас** action. Assigned project owners do not see the tab and
  receive HTTP 403 from the deployment endpoints.
- Added controller, authorization, generated UI, systemd asset, configuration,
  and deploy invariant tests; documented deploy-key setup, status inspection,
  rollback behavior, and advanced SUMMING to 8.6.0.
