# 2026-08-13

## Telegram help uses valid MarkdownV2

- Rebuilt `/help` and `/start` text from escaped plain-text, bold, and inline-code
  fragments so Telegram no longer rejects the response on reserved punctuation such
  as the hyphen in `gpt-transcribe` or parentheses in explanatory text.
- Added a regression check that scans both regular and administrator help for
  unescaped MarkdownV2 characters and unterminated formatting entities, and
  advanced SUMMING to 9.2.1.

## Silent unbound topics with explicit projectless Q&A

- Unbound Telegram group topics now remain silent during ordinary conversation:
  messages still update chat/topic discovery and a bounded volatile context window,
  but they create no pending input, ambient timer, Codex run, or `/bind` reminder.
- An explicit bot mention or reply in an unbound topic now starts a fresh read-only,
  network-disabled, projectless answer using only the direct question, general
  knowledge, and up to 20 recent topic messages/12,000 characters. It cannot inspect
  Project files, memory, editor/Q&A history, or attachments and does not bind the topic.
- Credential-like background messages are still deleted and audited without producing
  an unsolicited reply. Direct projectless questions use an isolated single-worker
  queue capped at four active/waiting requests, so they cannot consume Project capacity.
- Projectless threads are ephemeral, replies include the referenced bot answer, and the
  volatile topic rings use a 100-topic LRU cap with cleanup on binding or bot departure.
- Ephemeral threads disable environments and unsubscribe after use; stalled turns are
  interrupted after two minutes. A failed background credential deletion always warns
  the sender even though successfully deleted background credentials remain silent.
- Added routing and execution regressions for silence, topic discovery, bounded recent
  context, project isolation, and reply placement; documented the new boundary and
  advanced SUMMING to 9.2.0.

## Encrypted Connections with gateway, lease, and explicitly authorized raw access

- Added a separate `summing-secrets` trust domain with an envelope-encrypted
  SQLite vault, private master key, metadata-only audit, revoke/rotation
  versioning, one-use Ed25519 connection tickets, OAuth Authorization Code +
  PKCE, refresh-token confinement, and isolated public/control/runtime/gateway
  listeners. API keys and OAuth results are entered in a dedicated HTTPS UI;
  values never return through Viewer metadata, Telegram, or Codex.
- Added strict project integration manifests for `gateway | lease | raw`.
  Trusted provider capabilities bind names to exact HTTP methods and path
  prefixes. Viewer recommends gateway only when that capability exists, then an
  OAuth access-token lease, and otherwise raw. Long-lived raw delivery requires
  an explicit owner grant (`once` atomically consumed by the first job, or
  `project` until revoke); a connected raw credential without a grant blocks
  dry-run/live run.
- Wired the isolated runner to request credentials from the archived revision,
  materialize only per-job env under its `/run` tmpfs directory, mount only an
  opaque scoped token/socket for gateway mode, disable container networking for
  gateway-only jobs, revoke the lease and delete the env file in `finally`, and exact-redact job logs
  plus allowlisted dry-run artifacts. OAuth leases expose access-token fields
  only; raw grants and all runtime use are audited by project/integration/job.
- Closed the legacy bypass through project `.env`: static runner env files now
  accept only non-secret configuration and fail closed on credential-like names,
  forcing API keys/tokens/passwords through the manifest and audited broker.
- Added Telegram secret-ingress interception for messages, text attachments,
  and transcripts: matching input is not queued or persisted, deletion is
  attempted immediately, and only detector metadata is recorded. Added
  `/connections`, Viewer status/ticket/launch gates, raw-risk confirmation and
  reauthorization UI, same-origin Caddy routing, hardened systemd/install
  assets, provider registry examples, and the complete `CONNECTIONS_RU.md`
  threat model/runbook.
- Security regression coverage now exercises encrypted-at-rest storage,
  ticket replay, OAuth PKCE and refresh-token non-disclosure, capability/path
  boundaries, raw one-shot/project grants, runtime tmpfs cleanup, log/artifact
  redaction, Viewer authorization, Telegram deletion, key-file permissions,
  and deployment isolation. The complete suite passes 78/78 on Node 24 after
  rebasing onto SUMMING 9.1.0.

## Runner can create persistent dry-run artifact directories

  the persistent artifact path and make dry-runs fail before Docker starts.

## Persistent dry-run artifacts and themed Project Viewer

- Added a private allowlisted artifact channel between the isolated project
  runner and Project Viewer. Dry-run jobs receive immutable job/revision
  metadata and a dedicated path on the project's persistent data volume; the
  viewer can list, inspect, and download only `manifest.json`, `sources.jsonl`,
  `candidates.json`, `editorial-plan.json`, `errors.json`, and `report.html`.
- Records artifact counts on runner jobs, caps individual reads at 8 MB, rejects
  path traversal and non-dry-run access, keeps the latest 30 dry-run bundles,
  and raises an explicit client error instead of parsing truncated oversized
  runner responses.
- Expanded the Launch screen into a job workspace with log and artifact panes,
  native manifest metrics, full editorial post/source previews, diagnostics,
  raw file viewing, and downloads. Reworked the complete Mini App palette for
  dark/light Telegram themes using the supplied graphite, steel, and pink
  tokens, and replaced the temporary sigma mark with the supplied SUMMING logo.

## Auditable snapshot waiver for host migration

- Added an explicit `SUMMING_SNAPSHOT_WAIVED=1` apply mode for operators who
  intentionally accept migration without an external VPS snapshot. It is
  mutually exclusive with `SUMMING_BACKUP_CONFIRMED=1`, so the tool never asks
  an operator to make a false backup assertion.
- Both modes still stop services before capturing the server-local recovery
  bundle; its manifest now records `backup_mode`. Failure guidance distinguishes
  snapshot restoration from the riskier manual bundle-only recovery path.
- Updated the README, operations handbook, and deployment invariant tests to
  document and enforce the honest waiver contract.

## Guarded 8.x host migration to SUMMING 9.0

- Added an executable `deploy/migrate-host-to-summing` with a read-only
  `--check` mode and a snapshot-gated `--apply` mode. Preflight refuses active
  Codex runs, an active deploy worker, dirty source state, conflicting target
  users/paths/project IDs/branches/runtime directories, an unhealthy enabled
  runner, or a new GitHub remote that the existing deploy key cannot read.
- Apply stops polling and timers before copying a root-only recovery bundle with
  manifest, configuration, a consistent SQLite backup, old units, current link,
  and releases. It preserves UID/GID while renaming application, builder, and
  runner accounts; moves durable/config/repository paths; updates only
  operational configuration and secrets-file keys; relinks Codex; and keeps the
  preserved release artifacts recoverable rather than deleting them.
- Migrates stored self-project IDs/names and absolute paths transactionally,
  repairs linked Git metadata, renames conversation branches and reserved
  runtime directories without touching uncommitted files, refreshes identity
  and context assets, retags rootless Docker build images, installs only SUMMING
  units, runs the standard activation pipeline, and verifies application and
  runner health.
- Documented the required publish → GitHub repository rename → VPS snapshot →
  checkout fast-forward → preflight → apply sequence in both the README and
  Russian operations handbook. Added executable/syntax and safety invariant
  tests, including explicit rejection of recursive deletion in the migration.

## Atomic origin deployment and administrator update settings

- Added one serialized deployment worker shared by a ten-minute systemd timer
  and a manual Project Viewer request watched through `systemd.path`; no public
  webhook endpoint or GitHub-hosted SSH credential is required.
- Production now builds exact `origin/master` snapshots in versioned release
  directories and atomically switches `/opt/summing-current`. The mutable
  `/opt/summing` self-change repository is fetched without pull, reset, checkout,
  index, or working-tree mutation.
- Deployments reject an unexpected pinned remote and non-fast-forward history,
  wait for active Codex runs to drain, restart both SUMMING and the isolated
  runner, verify their loopback health endpoints, and automatically restore the

- Builds run under a dedicated `summing-builder` account that cannot read the
