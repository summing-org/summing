# 2026-08-12

## Project Viewer, reproducible run diffs, and isolated project execution

- Added an owner-authenticated Telegram Mini App Project Viewer on a dedicated
  loopback port. It exposes a secret-filtered Git tree, regular text files,
  working diff including untracked files, commit history/diffs, per-Codex-run
  before/after patches, runner job status, and bounded logs. `/files` routes a
  group-topic owner through the bot's private chat so Telegram can provide
  signed Mini App `initData`; SSH-tunnel access uses a separate bearer token.
- Editor Runs now use a temporary Git index to create immutable before/after
  snapshot commits without touching the real branch or index. Their patches
  are stored under `run-artifacts/<conversation>/<run-id>` and survive restart.
- Added a Unix-socket project runner that accepts only immutable Git archives
  and fixed `build`, `validate`, `dry-run`, or `run` operations. Its deployment
  uses a separate `summate-runner` account and rootless Docker daemon; the main
  Summate/Codex user never receives the Docker socket. Containers are read-only,
  capability-free, resource-bounded, and receive only configured project data,
  config, and environment mounts.
- Added production provisioning for Docker BuildKit cache GC capped at 8 GB,
  Caddy HTTPS, an `ash-seo` project configuration, and a daily 09:00 Moscow
  systemd timer pinned to an explicit full commit SHA. Live execution rejects a
  dirty worktree; build/validate/dry-run may use an immutable temporary snapshot.
- Added Telegram auth, Git inspector, and runner integration tests; advanced
  Summate to 8.5.0 and documented the new security and operational boundaries.
- Made the runner integration fixture use the operating system temporary
  directory so the production verification suite works on both macOS and Linux.
- The production runner unit now receives the actual `summate-runner` UID from
  the installer instead of resolving system-manager `%U` as root and looking
  for the rootless Docker socket under `/run/user/0`.
- The rootless daemon user is explicitly added to the private `summate` group,
  and its user manager is refreshed when that membership first changes, so it
  can traverse the mode-0750 runner configuration without making secrets
  world-readable.

## Codex standalone executable inside restricted Linux sandbox

- Restricted editor and read-only profiles now resolve the configured
  `CODEX_BIN` through its symlink chain and grant read-only access only to the
  containing executable directory. This keeps the versioned standalone release
  executable available when Codex re-executes itself to launch a Bubblewrap
  command, fixing `execvp .../bin/codex: No such file or directory` without
  exposing the rest of `CODEX_HOME`.
- Added a symlinked standalone-release regression fixture and advanced the
  runtime to 8.4.1.
- Direct runs now stay silent while refreshing Telegram's native `typing` chat
  action every four seconds in the bound topic until the final response or
  failure cleanup. The first message contains the actual streamed answer and
  remains a reply to the user's request. Typing delivery is best effort and
  cannot interrupt the Codex turn.

## Telegram attachments and configurable audio transcription

- Telegram `document`, `voice`, `audio` and audio documents are now recognized;
  downloads are capped at the Telegram Bot API limit of 20 MB.
- Documents are durably queued in a private spool, restored with pending inputs
  after restart, and copied into Git-excluded
  `.summate-runtime/attachments` before a Codex turn. Attachment metadata is
  stored in the additive `pending_inputs.attachments_json` column.
- Archive bytes are never automatically extracted by the host. Codex is told to
  list entries first and may extract only into `.summate-runtime/tmp` in editor
  mode; the deployment now supplies `file` and `unzip`.
- Audio is sent to OpenAI's fixed `/v1/audio/transcriptions` endpoint using the
  exact `gpt-transcribe` model by default. Groq Whisper remains available as an
  explicit provider with `whisper-large-v3-turbo` or `whisper-large-v3`. Both
  API keys stay in the Summate host process, are excluded from the Codex App
  Server environment, and the local raw audio is deleted immediately after
  transcription.
- Production activation now installs and smoke-tests system `bubblewrap`, loads
  Ubuntu's `bwrap-userns-restrict` AppArmor profile, and therefore addresses the
  `bwrap: setting up uid map: Permission denied` startup failure.
- Version advanced to 8.4.0; config, runbook, help text, migrations and tests were
  updated for the new behavior.
