# 2026-08-12

## Telegram attachments and configurable audio transcription

- Telegram `document`, `voice`, `audio` and audio documents are now recognized;
  downloads are capped at the Telegram Bot API limit of 20 MB.
- Documents are durably queued in a private spool, restored with pending inputs
  after restart, and copied into Git-excluded
  `.summate-runtime/attachments` before a Codex turn. Attachment metadata is
  stored in the additive `pending_inputs.attachments_json` column.
- Archive bytes are never automatically extracted by the host. Codex is told to
  list entries first and may extract only into `.summate-runtime/tmp` in editor
  mode; the deployment now supplies `file` and `unzip`.
- Audio is sent to OpenAI's fixed `/v1/audio/transcriptions` endpoint using the
  exact `gpt-transcribe` model by default. Groq Whisper remains available as an
  explicit provider with `whisper-large-v3-turbo` or `whisper-large-v3`. Both
  API keys stay in the Summate host process, are excluded from the Codex App
  Server environment, and the local raw audio is deleted immediately after
  transcription.
- Production activation now installs and smoke-tests system `bubblewrap`, loads
  Ubuntu's `bwrap-userns-restrict` AppArmor profile, and therefore addresses the
  `bwrap: setting up uid map: Permission denied` startup failure.
- Version advanced to 8.4.0; config, runbook, help text, migrations and tests were
  updated for the new behavior.
