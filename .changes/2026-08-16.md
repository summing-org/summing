# 2026-08-16

## Runner pins application config to the submitted Git snapshot

- Added root-managed `configSourcePaths`: runtime actions now select a regular,
  non-symlink config from the exact extracted Git archive and mount it read-only,
  while the legacy absolute `configPath` mode remains available for other projects.
- Switched `ash-seo` to prefer `config.json` with `config.example.json` fallback for
  older pinned revisions, and stopped creating the stale duplicate
  `/etc/summing-runner/projects/ash-seo.config.json` on new installations. Release
  activation now refreshes the root-owned runner policy while preserving a legacy
  `envPath` until the encrypted-environment cutover is finalized.
- Covered fallback selection, unsafe/ambiguous source rejection and deployment
  assets, documented the code/config/env snapshot invariant, and advanced SUMMING
  to 9.8.5.

## Final Telegram answers preserve the Codex work log

- Direct Codex runs now retain authoritative completed `commentary` messages and
  place their bounded last 12,000 Unicode characters before the final answer in a
  native collapsed **«Ход работы · …»** block. The duration is measured from the
  start of the Telegram stream, while reasoning items, tool arguments, command
  output and diffs remain excluded.
- Expandable Telegram sections now compose, so an audio transcript and the work log
  remain separate collapsed blocks. Final rendering also deletes obsolete extra
  messages left by a longer intermediate stream instead of leaving stale commentary
  in the topic.
- Documented the App Server phase contract, added renderer/runtime coverage, and
  advanced SUMMING to 9.8.4.

## Deployment results notify the administrator in Telegram

- Added a root-produced, application-delivered deployment outbox. Successful
  updates now carry the previous/target versions and commit, while lint/build/test
  failures carry their phase plus bounded test counts and names. The secret-bearing
  Telegram environment remains unavailable to the deployment worker, and build log
  tails are never rendered into administrator messages.
- The runtime polls the outbox, sends each event only to `TELEGRAM_OWNER_ID`, and
  removes it only after Telegram accepts the message, so temporary delivery failures
  retry. It also observes the in-flight state before exposing health, allowing the new
  release to announce the very rollout that introduced this feature even though that
  rollout started under the previous worker.
- A migration cutover that completes on a later deployment tick now becomes a real
  `succeeded` attempt and emits the same success event instead of silently returning to
  `idle`. Updated the operator documentation and advanced SUMMING to 9.8.3.

## Projects support a primary owner and multiple co-owners

- Added a durable `managed_project_owners` membership table while retaining
  `managed_projects.owner_id` as the mandatory primary owner. Existing databases
  backfill every current owner into the new membership table on startup, and owner
  replacement is atomic so a Project can never be left without a primary owner.
- Extended the Project ACL to every assigned owner for bindings, editor runs,
  repository operations and encrypted environments. The primary owner has the same
  working permissions as co-owners and remains the single recipient of automatic
  Project binding notifications.
- Added administrator-only owner management to each managed Project card: add or
  remove co-owners and promote an existing owner to primary. Config Projects stay
  read-only, non-administrators cannot call the mutation API, and SUMMING advances
  to 9.8.2.

## Project owners manage their own encrypted environments

- Exposed an explicit environment capability in Project Viewer sessions after the
  server-side Project ACL succeeds. A managed Project owner can now open the **Энвы**
  tab and read or save only that Project/workspace; an owner of another Project and an
  ordinary participant still receive `403`, while the system administrator retains
  access to every Project.
- Kept optimistic revision checks, encrypted-at-rest storage and runner-owned variable
  validation unchanged. Updated the owner security contract and advanced SUMMING to
  9.8.1.
- Kept the active Mini App section visible in the horizontally scrolling mobile tab bar,
  including direct links to the owner-only **Энвы** section.
- Aligned the production `ash-seo` managed workspace from `ash-seo` to the runner's
  canonical `repo` scope with a root-only SQLite backup, preserving its encrypted
  environment and repository credential material.

## Deployment failures are inspectable from the administrator Mini App

- Split the isolated builder pipeline into explicit dependency, lint, test and prune
  phases. Every failure now records its phase, category and exit code; TAP failures add
  bounded passed/failed counts, up to 20 failed test names and a sanitized 12,000-character
  log tail. An unapproved origin is a terminal source-verification failure instead of an
  indefinitely polling `checking` state.
- Added a bounded history of 20 meaningful deployment attempts and exposed the validated
  current failure plus history through the administrator API. The responsive deployment
  card renders the active phase, test diagnostics, expandable log tail and prior outcomes;
  ordinary up-to-date checks do not evict useful failures.
- Split the administrator Mini App into focused “Управление” and “Система” tabs. Global
  update controls and deployment diagnostics now live in “Система”; active deployment
  polling stops when the administrator returns to project and Telegram management.
- Hardened the shared deployment directory with root ownership and sticky group-write
  semantics, root-owned state/history, safe `mktemp` writes and an independently tested TAP
  report helper. Updated the operational contract and advanced SUMMING to 9.8.0.

## Release checks follow the canonical SUMMING version

- Replaced three stale `9.5.4` assertions with checks derived from the canonical
  `SUMMING_VERSION` identity, so future releases cannot fail only because a duplicated
  test literal was missed.
- Aligned the package metadata, runtime identity, README and operator handbook on
  SUMMING 9.7.1. The deploy test gate remains mandatory; this patch supplies a new
  immutable commit for the failed 9.7.0 deployment to retry safely.
