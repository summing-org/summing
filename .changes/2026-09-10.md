# 2026-09-10

## Runner дожидается остановки контейнера после timeout и защищает очередь проекта

- Timeout Docker CLI больше не выдаётся за обычный ненулевой exit code. Job
  сохраняет `terminationReason`, `timedOutAt` и `timeoutMs`; последующая отмена
  пользователем или ошибка очистки не заменяет первоначальную причину.
- Перед запуском контейнера атомарно сохраняется `containerCleanupPending`.
  После завершения CLI runner выполняет `docker stop` с 10-секундным сроком,
  затем `docker rm --force` и проверяет результат. Только подтверждённое удаление
  или отсутствие контейнера позволяет завершить очистку. Ошибка Docker хранится
  отдельно в `containerCleanupError`, а подтверждение — в `containerStoppedAt`.
- Пока очистка не подтверждена, все workspace этого Project остаются в очереди;
  другие проекты используют свободные слоты. Pending-состояние переживает
  перезапуск runner, в том числе восстанавливается для старых running/cancelling
  jobs. Очистка повторяется каждые 30 секунд, при старте runner и по повторному
  `runner.cancel`. Эти повторы не запускают workload заново. `/health` показывает
  `blockedProjects`, а обзор объясняет причину ожидания вместо сообщения о
  свободных слотах.
- Сохранённые артефакты собираются и после timeout/ошибки. Journal
  `scenario-generation.json` добавлен в разрешённые JSON-артефакты и обработку
  скрытия секретов. До остановки контейнера и скрытия секретов API артефактов
  отвечает 409. Незавершённая очистка исключает metadata, зашифрованный env и
  артефакты job из retention; при восстановлении секреты берутся из сохранённого
  зашифрованного snapshot без нового запуска приложения.
- `SUMMING_RUNNER_DRY_RUN_TIMEOUT_SECONDS` задаёт отдельный срок dry-run
  (1–7200 секунд, стандартные 900). Новый 12-минутный бюджет сценария Ash Shorts
  оставляет 3 минуты на другие этапы контейнера; сборка image имеет отдельный
  timeout. Предел live-run сохранён.
- Проверено на Node 24.19.0: полный набор 361/361, включая независимый процесс
  контейнера, graceful/forced stop, гонку timeout/cancel, блокировку одного
  проекта, автоматическое восстановление без повторного submit, ручной повтор
  очистки и retention. После уточнения причины ожидания в обзоре повторно
  проверены 19/19 тестов scheduler-reliability, build/typecheck, `release:check`
  и `git diff --check`.
- Изменения подготовлены в отдельной ветке; production deploy и платные
  генерации в этой итерации не выполнялись.
